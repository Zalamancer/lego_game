## Where to Get Exact 3D Replicas

### Free / Open

1. **LDraw Parts Library** ⭐ recommended
   - URL: https://library.ldraw.org/
   - Direct download: https://library.ldraw.org/library/updates/complete.zip (~250MB, ~20,000 parts)
   - Format: `.dat` plain-text CSG-ish format (lines, triangles, quads, sub-part references)
   - License: CC BY 2.0
   - **three.js has a built-in `LDrawLoader`**: https://threejs.org/docs/#examples/en/loaders/LDrawLoader
   - Each part is identified by its LEGO part number (e.g. `3001.dat` is the 2×4 brick)

2. **LDraw Official Library mirror (GitHub)**
   - https://github.com/williamcollins/ldraw-libraries (community mirror)

3. **Mecabricks**
   - URL: https://mecabricks.com/
   - Browser-based editor, has its own well-modeled library
   - Can export to `.zmbx` / Blender. Not as easy to bulk-extract as LDraw.

4. **Brickhub.org**
   - Some rendered LDraw parts as glTF.

### Commercial / Reference only

- **BrickLink Studio** — free editor but assets are LEGO-licensed, **don't ship them**
- **LEGO official set images on lego.com** — copyrighted

### Conversion pipeline (recommended)

```
LDraw .dat  →  three.js LDrawLoader  →  THREE.Group
              (or)
LDraw .dat  →  LeoCAD/Studio export  →  .glb (preview/baking)
```

For a small game, **don't ship the whole 250MB library**. Pick the ~50 parts above, write a small script to pre-convert just those `.dat` files to `.glb` (or load via `LDrawLoader` at runtime from a local subfolder).

## three.js LDrawLoader — quick recipe

```js
import { LDrawLoader } from 'three/examples/jsm/loaders/LDrawLoader.js';

const loader = new LDrawLoader();
loader.preloadMaterials('ldraw/officialLibrary/LDConfig.ldr').then(() => {
  loader.setPartsLibraryPath('ldraw/officialLibrary/');
  loader.load('models/3001.dat', (group) => {
    group.scale.setScalar(0.04); // LDU → reasonable world units
    scene.add(group);
  });
});
```

Notes:
- LDraw uses **LDU units** (1 LDU = 0.4mm). 1 stud = 20 LDU. 1 brick height = 24 LDU.
- LDraw uses **+Y down** (yes, really) — `LDrawLoader` flips this for you.
- Materials handle solid, transparent, chrome, pearl, rubber automatically.

## Stud / Snap Grid Math (for our placement system)

```
1 stud (X,Z spacing) = 8.0 mm  → in our world units: 0.8 (scale 0.1)
1 plate height (Y)   = 3.2 mm  → 0.32
1 brick height (Y)   = 9.6 mm  = 3 plates
```

For snapping logic, treat the world as a grid of:
- `gridX` * 0.8 (stud columns)
- `gridZ` * 0.8 (stud rows)
- `gridY` * 0.32 (plate-height layers)

A 2×4 brick occupies `2 × 4 × 3` cells in this grid.

## Legal Recap (from prior research)

- ✅ Brick **dimensions** — geometric, not copyrightable
- ✅ **LDraw library** — CC BY 2.0, ship freely with attribution
- ❌ The word "LEGO" in title/marketing
- ❌ "LEGO" embossed on studs (LDraw studs are blank by default — keep them blank)
- ❌ Shipping BrickLink Studio's `.io` assets or LEGO official renders
- ❌ Replicating specific LEGO **sets** (e.g. Millennium Falcon model #75192) — that's a creative work

### How to run the demo

```bash

python3 -m http.server 8000          # any local server works
# open http://localhost:8000/index-ldraw.html
```

### Why a separate file (not folded into index.html)?

The main `index.html` uses **procedural** brick generation: pick a footprint
(2×4, 6×6, etc.) and the code draws a parametric box + studs. This is
infinitely flexible but the geometry isn't exact LEGO.

LDraw parts are **fixed pre-modelled meshes**. Each part is one specific LEGO
piece. They're exact, but you can't "stretch" them to arbitrary sizes.

The two systems can coexist:
- Procedural bricks → core build palette (any size)
- LDraw parts → specialty pieces (slopes, curves, jumpers, technic)

Once you've kicked the tires on `index-ldraw.html`, we can decide:
- (a) replace procedural bricks entirely with LDraw equivalents
- (b) add an LDraw "Special Parts" panel to the main app (keep procedural for boxes)
- (c) keep `index-ldraw.html` as a reference and stay procedural

### Caveat for deploying

`assets/ldraw/` is ~80MB. Don't commit it. For production we'd either:
- ship only the ~50 parts we use (but they reference primitives in `p/`, so still ~5MB)
- or load from a CDN mirror at runtime
